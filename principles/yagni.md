# YAGNI Principle

YAGNI stands for **You Aren't Gonna Need It**.

The idea is simple: do not build features, abstractions, or code for future possibilities that are not required right now.

## Why It Matters

- Extra code increases maintenance cost.
- Unused features make systems harder to understand.
- Premature additions often introduce avoidable bugs.
- Teams move faster when they focus on current requirements.

## How to Apply YAGNI

- Implement only what is needed for the current use case.
- Delay future-facing code until there is a real requirement.
- Remove speculative logic that has no current consumer.
- Prefer small, incremental changes over big predictive designs.

## Important Clarification

YAGNI does **not** mean ignoring planning. It means avoiding speculative implementation and building when actual needs are confirmed.
